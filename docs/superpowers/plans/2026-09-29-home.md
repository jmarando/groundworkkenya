# Home (part 1 of the Home, Voters and race data spec): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Overview and Briefing become one Home page. It reads Today → The race → Our
campaign, with no Demo/Live tabs and no race switcher. Each section says whether it
is real or sample, and every number opens the screen it comes from.

**Architecture:** A pure module (`src/lib/home.ts`) decides which sections are real,
builds the Today list and holds the metric links. A loader (`loadHome`) reads the
real signals under the user's own access rules. The page is composed from the
existing briefing and overview components, re-ordered under three section heads.
`/overview` and `/briefing` forward to `/home`. A migration tags the 1,200 seeded
people as `sample`.

**Tech stack:** TanStack Start/Router, React, Supabase (RLS), tsx tests, and the SQL
harness.

Spec: `docs/superpowers/specs/2026-09-29-home-voters-race-design.md`, section 1.

## Global constraints

- Every campaign table keeps `campaign_id` and the restrictive own-campaign policy.
  The loader runs as the signed-in person, so RLS scopes every count.
- A sample section always shows its "Sample" tag. Real data is never labelled
  sample, and sample is never shown untagged.
- The public repo holds no secrets and no voter data.
- Don't reformat whole files (pre-existing prettier errors); lint only the changed
  lines.
- Production changes (migration 15, publish) need the user's OK.

## Task 2: The Home rules (pure)

**Produces (src/lib/home.ts):**
```ts
export type SectionMode = "real" | "sample";
export type HomeFacts = { realPeople: number; rivals: number; polls: number };
export type RealSignals = {
  pendingExpenses: number;
  unread: number;
  topIssue: { label: string; count: number; angry: number } | null;
};
export type TodayItem = { title: string; detail: string; action: Action; sample: boolean };
export function sectionModes(f: HomeFacts): { race: SectionMode; campaign: SectionMode };
export function realToday(sig: RealSignals): TodayItem[];
export function todayItems(real: TodayItem[], sample: Scenario["today"], max?: number): TodayItem[];
export function topIssue(rows: { issue: string | null; sentiment: string | null }[], min?: number): RealSignals["topIssue"];
export function greetingName(fullName: string | null | undefined, fallback: string): string;
export function raceVerdict(s: Scenario): string; // "Second, 1.0 points behind Rival." or "Leading Rival by 2.0 points."
export const LINKS: { agents: "/agents"; money: "/finance"; contacts: "/people"; supporters: "/people"; doors: "/canvassing"; ground: "#ground"; race: "#race" };
```
- [ ] Tests in `tests/home.test.ts`:
  - `sectionModes`: nothing → both sample; a poll only → race real; one real person →
    campaign real.
  - `realToday`: two pending expenses → "2 expenses to approve", linked to Finance;
    one unread → "1 person waiting for a reply", linked to Inbox; a top issue →
    "Floods is the loudest issue this week" with its count and share angry, linked
    to Listening; zeros → none.
  - `todayItems`: real items come first; sample items fill up to three and are marked
    `sample`; never more than three.
  - `topIssue`: counts by issue ignoring case and blanks; below the minimum of 3
    gives null; `angry` counts negative sentiment.
  - `greetingName`: "Njeri Kamau" → "Njeri"; blank → the fallback.
  - `raceVerdict` on the three scenarios: the Sakaja sample (us 42, a 40 in the
    last week) → "Leading <a's short name> by 2.0 points."; made-up shares putting us
    second → "Second, …".

## Task 3: Loading the real signals

**Produces:** `loadHome(sb, userId, role): Promise<HomeData>` and the `getHome` server
function. `HomeData = { firstName: string | null; facts: HomeFacts; signals: RealSignals }`.
Queries run as the user:
- `profiles.full_name` for `userId`.
- A count of people without the sample tag (`.not("tags", "cs", "{sample}")`).
- Pending expenses, counted only when the role can approve (super, candidate,
  manager); otherwise 0.
- Unread conversations.
- `listening_mentions` `issue, sentiment` for the last 7 days (up to 2,000), reduced
  with `topIssue`.
- `facts.rivals = facts.polls = 0` until part 2 adds race tables.
- [ ] Tests (fake Supabase): a sample-tagged person is not counted and an untagged one
      is; an organiser sees 0 pending expenses and a manager sees the count; unread
      is counted; mentions older than 7 days are ignored.
- [ ] Add `not(col, "cs", value)` to `tests/fake-supabase.ts` (true when the array
      column does not contain every listed element).
- [ ] Implement, pass, commit.
